## 2. 레이아웃 선택표 (언제 무엇을, 왜)
| 창 | 레이아웃 | 이유 |
|---|---|---|
| 폰(접힘, <600dp) | `장면 고르기` 보드가 먼저. 장면을 누르거나 하단 `선택한 장면 편집`으로 미리보기·스크롤 편집 화면을 열고, 뒤로 가면 같은 보드 위치. 보드 하단은 `재료 추가`·`선택한 장면 편집`, 편집 화면 하단에 주 행동(영상 만들기→폰하드에 저장). (2.33.2) | 적은 폭을 보드와 상세에 각각 충분히 쓴다. |
| 태블릿 세로(≈790dp) | 레일 + 본문. 위 약 45%에 4열 `장면 고르기` 보드, 아래 나머지에 `선택한 장면 편집`(미리보기→탭→스크롤 인스펙터)과 맨 아래 주 행동. 접기 토글은 없다. 키보드가 뜨면 보드가 약 25%로 줄어든다. (2.33.2) | 장면 목록을 유지하면서 선택한 장면을 고친다. |
| 태블릿 가로(≈1080dp) | 파일 탐색은 기존 소스 사이드바·본문. 편집기는 머리 아래 좌우 1:1 분할: 왼쪽은 고정 4열 `장면 고르기` 보드, 오른쪽은 `선택한 장면 편집`(미리보기·스크롤 인스펙터)과 그 맨 아래 주 행동. (2.33.2) | 많은 장면을 한눈에 찾고, 먼 위치는 번호로 바로 옮긴다. |
| 접힌 폰으로 돌아가기 | 위 규칙이 창 크기만으로 결정(기기 이름 분기 금지). | 폴더블·분할 화면에서도 같은 계약. |

- 편집 화면은 상태 표시줄(시계·배터리·시스템 아이콘)을 표시하고 안전 영역 안에 도구를 배치한다. 명시적 전체화면 재생에서만 상태 표시줄을 숨기며 돌아오면 복원한다. 2.32.0에서 TriFold 가로·세로와 Fold6 커버의 상태 표시줄·안전 영역을 확인했다. 키보드가 올라오면 미리보기를 줄이고 인스펙터를 스크롤하며, 헤더는 화면 위로 밀리지 않는다.

## 3. 파일 탐색 · 클립보드 · 선택
- 경로 막대(루트 연결 이름 › 폴더…)는 항상 보이고, 각 조각을 누르면 그 폴더로 이동. 상위 폴더 버튼 별도.
- 선택 모드: 닫기(×), "N개 선택", "전체 선택", 하단 행동 막대(복사·이동·삭제 …). 선택 표시는 체크 + 행 강조.
- 복사/이동은 클립보드 배너로 이어진다: **무엇을**(`‘파일명’ 외 N개`) · **어디로**(현재 폴더 경로) · `취소` · `여기에 복사/이동`. 폴더를 탐색하는 동안 배너가 유지된다.
- 소스가 다르면(폰하드→NAS) 목적지 선택지를 먼저 묻는다: NAS·네트워크 / 내 휴대폰 폴더 / 폰하드 안 다른 폴더. 각 선택지에 "ZIP 없이 원래 이름", "덮어쓰지 않고 번호" 같은 결과 문장을 붙인다.
- 폰하드↔NAS·내 폰 폴더는 위 목적지 선택으로 바로 복사·이동(업로드/다운로드)한다. 서로 다른 네트워크 연결 사이(NAS A → NAS B 등)는 자동 중계가 없으므로 "다운로드 → 업로드" 두 단계로 안내한다.
- 헤더 개수는 보이는 항목 수와 같아야 한다(폴더+파일을 두 번 세지 않는다).

## 4. 감상 계약 (재생·전체화면·복귀)
- 목록 탭 → 앱 내장 플레이어. 컨트롤: 닫기, 제목, 공유 / 이전·다음, 탐색 막대, 현재/전체 시간, 재생·일시정지, 재생 모드. 컨트롤은 화면 가장자리에 걸리지 않는다.
- 가로 전체화면에서도 같은 컨트롤. 세로 영상은 필러박스(자르지 않음).
- Back = 플레이어 닫고 **같은 목록 위치**로 복귀. 재열기 시 앱이 재생 위치를 복원할 수 있으면 복원(Android는 표시만 확인).
- 직접 연 로컬 영상이 내장 재생에 실패하면 시스템 플레이어 선택창으로 넘기며, 돌아오면 "다시 시도/닫기"를 남긴다. 원격 영상은 사용자가 버튼을 눌러야 외부 재생을 준비한다. 앱이 만든 영상은 **내장 플레이어에서 재생 가능한 인코딩**이어야 한다(H.264 ≤1080p는 Level 4.1 이하 요청. Fold6 인코더가 Level 6.0을 기록해 같은 기기 내장 재생이 실패한 사례).
- 재생 종료 후 다음 항목으로 이동하는 방식은 재생 모드로 선택한다. 자동으로 넘어간 다음 항목이 재생되지 않으면 앱 안에 오류와 외부 플레이어 버튼을 보여 주며, 시스템 선택창을 임의로 띄우지 않는다.

## 5. 영상 제작 계약 (가져오기 → 편집 → 렌더 → 저장 → 재열기)
- 진입: 새 프로젝트 + **편집본 목록**(기존 편집본 목록 재사용, 별도 저장소 없음).
  - 2.32.6: 영상 제작 화면의 최근 편집본 단일 행을 없애고, 작업대/미디어 고르기 아래에 `편집본 N개` 섹션과 실제 편집본 목록을 둔다. `TrailerDraftStore.getAllDrafts()`(비공개 모드 필터·최신순)만 IO에서 읽고 LazyColumn `items(key = id)`로 행마다 64×48 표지(`rememberTrailerDraftCover` 160px 비동기, 없으면 영상 아이콘)·두 줄 제목·모드·미디어 수를 보인다. 탭하면 기존 `resumeTrailerDraft`로 열고(없는 편집본도 기존 처리), 새 버튼·메뉴는 없으며 이름 변경·삭제는 편집본 탭이 맡는다. 목록 읽기 실패는 `metadataProblem` 문구를 오류색으로 그대로 보인다. Fold6·TriFold에서 작은 표지와 제목·재료 개수 표시, 행 선택 후 올바른 편집본 열기를 확인했다. TriFold의 읽기 불가 정보 1건 경고도 그대로 보였고, 읽히는 2건은 보존되어 있다. 읽기 불가 항목의 복구는 이번 화면 변경에 포함하지 않았다.
- 편집 상태를 항상 구분 표기: 장면 미리보기 / 만든 영상(현재) / 이전 영상(수정 전) / 영상 만드는 중.
- **주 행동 하나 (2.33.1, 위치는 2.33.2에서 변경 — 아래 §16):** 영상 만들기(렌더)와 폰하드 저장(최종 결과 보관)은 다른 단계다. 같은 자리 주 버튼이 상태에 따라 바뀐다: 현재 영상 없음 → `영상 만들기`, 만든 뒤 편집함 → `수정본 만들기`, 현재 영상이 폰하드에 없음 → `폰하드에 저장`, 저장 완료 → `저장됨`(비활성). 진행 중에는 `영상 만드는 중…` / `폰하드에 저장 중…`(비활성). 렌더 완료는 저장 완료로 보이지 않는다(버튼 이름이 `폰하드에 저장`/`저장됨`으로 구분). 2.33.2부터 이 정상 상태를 따로 알리는 상태 줄(`영상 준비됨 · 폰하드에 저장해 주세요`, `폰하드에 저장됨`, `수정 내용으로 영상을 다시 만들어 주세요`)은 없다. 편집본(프로젝트) 자동 저장은 `편집본 자동 저장됨 / 편집본 저장 중… / 편집본 저장 실패`로 따로 표기한다. 새 마법사·버튼·선택지는 없다. 공유·컬렉션 보관·전체화면과 보조 `폰하드에 저장` 칩은 미리보기 아래에 그대로 둔다.
- 만든 영상이 **현재(revision 일치)** 일 때만 공유·폰하드 저장·컬렉션 보관 활성. 수정되면 `수정본 만들기`를 먼저 안내. 이름만 바꾸면 영상은 현재로 유지.
- 폰 편집기: 장면 보드와 상세 편집을 오간다(§13). 상세 편집은 미리보기 → 탭 → 스크롤 편집 패널 → 하단 고정 주 행동이며, 보드 하단은 `재료 추가 / 선택한 장면 편집`(2.33.2). 완성본 행동 칩은 폭이 좁으면 **줄바꿈**한다.
- 저장 영수증: "폰하드에 저장됨"은 편집본 폴더의 영수증(완성본 리비전 + 폰하드 레코드 ID + 그 완성본 출력 파일 이름)으로 판단해 재열기 후에도 유지. 세 값이 모두 맞아야 저장됨이다 — 수정 없이 **다시 만든** 새 영상은 리비전이 같아도 출력 파일이 달라 다시 저장할 수 있다. 이름·크기만으로 중복을 추정하지 않는다. 폰하드 파일을 지우면 영수증은 무효가 되어 다시 저장 가능. 예전 2줄 영수증은 "저장 안 됨"으로 안전하게 취급.
- 렌더 결과 검증: 지정한 장면 순서·길이와 일치(프레임 대조), 출력 방향은 첫 소스 비율 규칙을 화면 형식 설정에서 바꿀 수 있음.

## 6. 오류·빈 상태
- 빈 폴더: "빈 폴더 / 이 폴더에는 표시할 파일이 없습니다." 보관함이 비어 보일 때는 목록을 다시 읽은 뒤에만 빈 상태를 보인다.
- 연결 불가·권한 없음: 원인과 다음 행동(다시 연결, 권한 허용)을 한 문장으로.
- 파괴적 실패(이동 중 원본 삭제 실패 등): 복사본이 남았다는 사실을 문장으로 알린다.

## 7. Android 실기기에서 확인한 것 vs 확인하지 않은 것
영상 처리 확인(2.31.1 APK, 2.31.2에서 해당 처리 코드 불변): 사진 카메라 무빙(§12) — 실제 사진 16:9→9:16 저장본·세로 사진→16:9 저장본 프레임 검사, 저장→수정 없이 다시 내보내기→닫기/재열기→다시 저장→재열기 저장됨, 예고편·뮤비 저장 파일명, 태블릿 세로 쌓기·가로 인스펙터·폰 커버 레이아웃, 기존 NAS 연결 유지.
이전 빌드에서 확인하고 코드가 바뀌지 않은 것(2.31.0): 폰 폭 편집기 스크롤·하단 고정 행동, 칩 줄바꿈, 최근 편집본 바로가기, 저장 영수증(저장→이름 변경→뒤로→재열기 유지), 폰 내장 재생(재생/탐색/뒤로), 패드 세로 쌓기 편집기·가로 편집기, 패드 NAS 폴더 만들기·복사·이동·이름 변경·삭제(취소 후 삭제)·기기에서 올리기·다운로드(번호 붙임)·폰하드→NAS 보내기, NAS 스트리밍 재생(세로/가로).
미확인: 펼친 Fold6, 접힌 TriFold, NAS↔NAS 다른 연결 간 복사, 재생 위치 복원, 접근성 글자 크기, 저장본의 순간 카메라 속도 실측(속도 한계는 단위 시험에서 렌더 경로를 표본 추출해 확인, 기기에서는 프레임으로 경로만 확인).

## 8. 이후 iPhone / iPad / Mac 적용 제안 (미구현 · 제안)
Android 사실을 **의미 계약**으로 가져가고 표현은 각 플랫폼 관용을 따른다.

## 11. 저장 파일명·기본 제목
- 새로 만드는 저장 파일명과 자동 기본 제목: `yyMMdd-HHmmss-예고편`, 뮤직비디오 모드는 `yyMMdd-HHmmss-뮤비` (2자리 연도, 24시간, 기기 현지 시각). 예: `261031-104300-예고편.mp4`, `261031-104300-뮤비.mp4`.
- 적용: 폰하드 저장 파일명, 외부 공유 임시 파일명(캐시 키 폴더 아래 친근한 이름, 공유 제공자 허용 범위 `cache/shares` 유지), 완성본 컬렉션 보관 대화상자의 기본 제목(사용자 지정 제목이 있으면 그대로).
- 기존 파일·사용자 제목은 이름을 바꾸지 않는다(이관 없음). 같은 이름은 기존 "(1)" 보존 규칙.
- 실기기에서 예고편 3건과 뮤비 1건의 폰하드 저장 이름을 확인했다. 예고편 2건은 SAF로 내려받아 저장 이름과 영상 프레임까지 대조했다. 뮤비 이름은 폰하드 목록과 편집본 재열기에서 확인했다.

## 12. 사진 장면 카메라 무빙 (채우기/맞추기)
- **채우기는 어느 프레임에서도 레터박스가 없다.** 매 프레임 보이는 창은 사진 안에 있고(폭 ≤ min(1, 1/k), 높이 = 폭·k ≤ 1, k = 사진비/출력비), 축소는 꽉 차는 기준에서 멈춘다. 분석 실패·인물 여러 명·지정 구도·첫/끝 프레임·짧은 장면 모두 같다. 채우기가 자동으로 맞추기나 흐린 배경으로 바뀌지 않는다.
- **맞추기**는 사용자가 고른 경우에만, 사진 전체(레터박스 포함)를 보이며 살짝 확대·이동한다.
- 경로: 시작은 사진마다 고정된 무작위 구도(같은 사진은 미리보기·내보내기·재열기에서 같은 경로) → 다른 인물/주요 지점 → **마지막은 주인공**(가장 큰 얼굴 묶음, 머리 여백 포함). 인물이 없으면 가장 큰 검출 피사체, 그것도 없으면 사진 가운데(의미 보장 없음). 이동 중에는 꽉 차는 기준 쪽으로 살짝 빠졌다가(당기기) 다음 인물로 밀어 들어간다. 16:9→9:16은 가로로, 세로 사진→16:9는 세로로 움직인다. 분석은 기기 안(ML Kit)에서만 한다.
- **시간 고려(무리한 무빙 금지):** 어떤 순간에도 이동은 초당 화면 폭(세로 이동은 화면 높이)의 0.4배 이하, 확대·축소는 초당 |Δln(폭)| 0.12 이하. 장면 길이 안에 이 속도로 갈 수 있는 만큼만 들른다 — 중요한 인물부터 넣고, 못 들르는 인물은 건너뛴다(서두르지 않음). 시작 구도도 남은 시간으로 갈 수 있는 거리 안에서만 무작위다. 남는 시간은 이동을 더 느리게(최대 1.6배) 하고 마지막 머무름을 늘린다. (3초 초과 장면 규칙, 2.32.2에서 변경 없음)
- **3초 이하 장면(2.32.2, 짧은 장면 이동 제한):** 가로·세로 이동, 여러 지점 들르기, 무작위 시작, 당기기(빠졌다 들어가기) 없음. 모든 키프레임이 같은 중심 — 지정 구도가 있으면 그 구도, 없으면 주인공 머리 묶음(머리 여백 포함), 없으면 주요 피사체, 없으면 사진 가운데를 꽉 차는 가장 넓은 창에 담는 중심. 이 중심은 꽉 차는 폭에서 이미 사진 안이라 확대해도 가장자리 보정으로 중심이 밀리지 않는다(가장자리 얼굴 포함). (2.33.0) 길이가 양수이고 유한하면 아무리 짧아도 고정하지 않고 한 방향으로만 살짝 확대(3초에 최대 4%, 길이에 비례 — 0.3초면 0.4%, 4%를 0.04초에 몰아넣지 않음)하되 주인공(지정 구도면 그 안의 인물) 전체가 화면 안에 남는 만큼만; 꽉 찬 창에도 다 안 들어가면 확대 없이 고정(사유는 얼굴·피사체 보호이며 길이가 아님, 편집기 표시 "…고정 (확대하면 잘림)"). 아주 작은 안전한 확대량도 버리지 않는다. 길이가 0 이하이거나 알 수 없을 때만 길이 때문에 고정한다. 1~2프레임짜리 장면은 확대량이 프레임 사이에 거의 드러나지 않으며, 사용자가 정한 길이는 자동으로 늘리지 않는다. 채우기는 매 프레임 레터박스 없음. 맞추기는 사진 전체를 유지한 채 가운데 고정으로 살짝 넓은 창 → 딱 맞는 창(최대 4%)으로만 들어가며 채우기로 바뀌지 않는다. 미리보기·내보내기 같은 계획(무작위 없음). TriFold에서 3초 합성 사진 장면을 포함한 확인용 11초 편집본을 다시 제작·폰하드 저장·재생했고 초반 두 시점에서 큰 위치 이동 없이 표시되는 것을 확인했다. 가장자리 실제 얼굴의 정밀 프레임 대조는 이번 확인에 포함하지 않았다.
- 장면 길이: 새 자동 사진 장면은 최소 3초. 사용자가 정한 장면 길이는 자동으로 늘리지 않는다 — 짧게 정하면 들르는 인물이 줄어들고 편집기 표시(예: "인물 1/3곳 · 마지막 주인공")가 실제로 들르는 수를 그대로 말한다. 16:9 사진을 9:16으로 세 사람을 모두 들르려면 대략 20초 안팎이 필요했다.
- 지정 구도(보이는 위치)를 바꾸면 그 구도가 마지막 구도가 되고, 그 안의 인물이 잘리지 않을 만큼만 밀어 들어간다. 채우기 규칙은 그대로.
- 미리보기와 내보내기는 같은 계획·같은 행렬을 쓴다. 내보내기는 방향을 적용한 원본 사진 전체를 넣어 GL에서 한 번만 자른다(이중 자르기 없음).
- Apple 적용 시(미구현 · 제안): 같은 순수 기하(창 = 중심·폭, 매 프레임 사진 안으로 고정)와 같은 속도 한계·같은 사진별 시드를 쓰고, 얼굴/피사체 검출은 Vision으로 대체. 수용 기준은 아래와 같다.
  - [ ] 채우기 모든 프레임 네 모서리가 사진 픽셀.
  - [ ] 마지막 프레임에 주인공 얼굴 전체.
  - [ ] 렌더 경로를 표본 추출한 최대 이동·확대 속도가 한계 이하.
  - [ ] 같은 사진은 다시 열어도 같은 시작 구도, 사진마다 시작은 다름.

## 13. 장면 보드 편집 (2.32.0)
- **레이아웃:** 펼친 가로(폭 ≥ 840dp·높이 ≥ 480dp)는 좌우 1:1로 왼쪽에 고정 4열 장면 보드, 오른쪽에 장면/완성본 미리보기와 스크롤되는 기존 인스펙터(2.32.1 조정). 펼친 세로는 위에 미리보기+인스펙터(접기 가능), 아래에 남은 높이를 쓰는 보드. 폰(세로 접힘)과 폰 가로·높이 560dp 미만 창은 보드가 화면을 채우고, 장면을 누르거나 "상세 편집"으로 미리보기+인스펙터 상세 화면을 열며, 뒤로 가기는 먼저 상세를 닫고 보드 스크롤을 유지한다. 폭이 좁은 창을 억지로 두 칸으로 나누지 않는다.
- **미리보기 크기 (2.32.4, 드래그 핸들):** 세 레이아웃(펼친 가로·펼친 세로·폰 상세) 모두 그림 바로 아래, 완성본 행동 칩 위에 폭 전체를 쓰는 24dp 높이 드래그 영역만 있다(2.32.5: 안내 문구와 채운 배경 없이 가운데 36×3dp 얇은 손잡이 막대만 보이는 구분선 형태, 접근성 이름은 유지). 별도 크기 조절 버튼과 수치 표시는 없다. 작게 하려면 핸들을 위로 끈다. 그림의 아래 가장자리를 잡듯 핸들을 아래로 끌면 커지고 위로 끌면 작아진다(표준 Compose `draggable(Orientation.Vertical)`, dp 단위 이동량). 배율은 실제로 그려진 그림 높이를 기본 높이로 나눠 계산하므로 출력 비율·패널 높이 상한에 걸려도 숨은 초과분 때문에 되돌릴 때 반응 없는 구간이 생기지 않는다. 퍼센트 표시나 별도 수치 조절은 없다. 핸들은 그림 밖에 있어 드래그가 영상 탐색·재생을 시작하지 않는다. 화면에 보이는 그림 높이만 바뀌는 UI 설정이며 원본·내보내기 구도, 출력 비율, 편집본 저장·리비전·실행 취소에는 들어가지 않는다. 값(`rememberSaveable` previewScale, 50~200%)은 편집 화면 하나를 공유해 회전·보드↔상세 왕복 뒤에도 유지된다. 커져도 그림은 패널 폭(출력 비율 기준)과 패널 높이의 일정 비율(가로 50%·폰 상세 45%·세로 34%)을 넘지 않아 헤더·탭·인스펙터·하단이 계속 닿는다. 키보드가 올라오면 핸들을 숨기고 기존의 작은 안전 크기로 돌아간다. 핸들은 접근성 이름("미리보기 크기 조절, 위아래로 드래그")과 "미리보기 크게/작게" 사용자 지정 동작을 가진다. 2.32.4 실기기에서 TriFold 아래 드래그로 확대·위 드래그로 축소, 세로 회전 후 화면 유지, Fold6 상세에서 위 드래그 축소, 별도 크기 버튼 부재를 확인했다. TalkBack과 최종본의 키보드 조작은 별도 확인하지 않았다. 2.32.5 얇은 핸들의 Fold6·TriFold에서 작은 표지와 제목·재료 개수 표시, 행 선택 후 올바른 편집본 열기를 확인했다. TriFold의 읽기 불가 정보 1건 경고도 그대로 보였고, 읽히는 2건은 보존되어 있다. 읽기 불가 항목의 복구는 이번 화면 변경에 포함하지 않았다.
- **보드:** 지연 로딩 여러 줄 격자(수백 장면), 장면 번호(프로젝트 안 1부터의 순서이며 재료 개수가 아님)·재생 시간·원본 파일 이름·사진/영상 표시, 회전·상세 복귀 시 스크롤 유지. 2.33.2에서 작게/보통 크기 전환과 번호·파일 이름 검색·번호 바로 이동은 없앴고 모든 장면을 프로젝트 순서대로 보인다(먼 위치는 `위치 이동` 번호 대화상자).

## 14. 장면 자막 (2.32.0)
- 장면마다 선택 사항인 수동 자막 하나. 그 장면 전체 길이 동안 출력 화면 기준으로 고정되며 사진 무빙·화면 위치와 함께 움직이지 않는다. 자동 음성 인식은 없다.

## 16. 편집 순서 재배치 (2.33.2)
- 순서는 화면 위치로 드러난다: `장면 고르기`(보드) → `선택한 장면 편집`(미리보기 → 탭 → 스크롤 인스펙터) → 편집 영역 맨 아래 주 행동. 새 단계 표시·마법사·옵션·기능은 없다.
- 펼친 가로: 머리(닫기·프로젝트 이름·자동 저장 상태·실행 취소/다시 실행)와 렌더 진행 줄이 전체 폭, 그 아래 왼쪽 4열 보드 | 오른쪽 편집 창(작은 제목 `선택한 장면 편집 · N번 장면`, 미리보기, 24dp 손잡이, 탭, 스크롤 인스펙터, 맨 아래 주 행동 한 줄).
- 펼친 세로: 머리 → 보드(남은 높이의 약 45%, 4열, 자체 스크롤) → 편집 영역(약 55%: 제목, 미리보기, 탭, 스크롤 인스펙터, 맨 아래 주 행동). 키보드가 뜨면 보드 25% / 편집 75%.
- 폰: 보드가 먼저이고 보드 하단은 `재료 추가`·`선택한 장면 편집`(선택 장면이 있을 때만). 보드에는 영상 만들기/저장이 없다. 상세 화면은 뒤로·`N번 장면 편집`·실행 취소/다시 실행 → 미리보기 → 탭 → 스크롤 인스펙터 → 맨 아래 주 행동. 뒤로 가면 같은 보드 위치.
- 주 행동(`영상 만들기`/`수정본 만들기` → `폰하드에 저장` → `저장됨` 비활성, 진행 중 `영상 만드는 중…`/`폰하드에 저장 중…`)은 머리·폰 상세 머리에서 빠지고 편집 영역 맨 아래 고정 줄에만 있다. 스크롤 안에 숨지 않는다. 미리보기 옆 완성본 칩은 `전체화면`·`공유`·`컬렉션에 보관`만 남고 폰하드 저장 칩과 수정본 버튼 중복은 없앴다.
