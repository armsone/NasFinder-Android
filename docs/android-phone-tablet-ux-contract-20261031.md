# NasFinder Android 폰·태블릿 적용 기준 (2026-10-31)

상태: **Android 적용·검증 기록**. Android 2.32.0(435700)의 적용 기준과 실기기 점검 범위를 정리한 것이며, iPhone/iPad/Mac은 아직 구현·검증하지 않았습니다. 이 문서는 프로젝트 문서이고 개인 메모리가 아닙니다.
검증 기기: Galaxy Z Fold6(접힘 커버 화면 968x2376, 폰 뷰포트), Galaxy Z TriFold(펼친 내장 화면 세로 1584x2160 / 가로 2160x1584). 시각 점검은 개발자 직접 관찰이며 사용자 검증이 아닙니다.

## 0. 근거(저장된 디자인 사례, 새 웹 검색 없음)
- UXDA-2026-ZINGTREE: 편집 단위(장면)와 미리보기를 한 시야에 두고, "지금 대상"과 "다음 행동"을 항상 보이게 한다.
- UXDA-2026-KTM-DASHBOARDS: 방향·폭마다 따로 맞추고, 현재 상태와 행동을 우선한다. 화면이 커졌다는 이유로 장식·정보를 더하지 않는다.
- 적용 원칙: (1) 큰 화면은 "더 많은 것"이 아니라 "같은 것을 덜 넘기며" 보여 준다. (2) 위험한 작업은 대상·위치·결과를 말로 확인시킨다. (3) 실패는 성공처럼 보이지 않게 한다.

## 1. 공통 작업·상태·데이터 의미 (플랫폼 무관, 반드시 동일)
| 작업 | 의미 계약 |
|---|---|
| 소스 | 폰하드(앱 보관함), 내 폰 폴더(시스템 폴더 선택기), NAS/네트워크 연결(저장된 연결). 목적지 선택 화면은 어느 쪽인지 이름·주소를 보여 준다. |
| 복사 | 원본 유지. 같은 이름은 덮어쓰지 않고 번호를 붙인다(`name (1).txt`). |
| 이동 | 목적지에서 크기 확인 후에만 원본 삭제. 확인 못 하면 원본을 남기고 "이동 못 함"으로 알린다. 부분 성공은 개수로 보고한다. |
| 삭제 | 항상 확인 대화상자(대상 이름/개수, 되돌릴 수 없음 명시). 취소하면 선택·목록 그대로. |
| 이름 변경 | 같은 폴더 안 이름만 바꿈. 내용 편집기는 없다. 잘못된 이름은 거부하고 이유를 보인다. |
| 성공 | 방해하지 않는 짧은 안내(토스트). 목록은 즉시 새로 고침. |
| 실패·부분 성공 | 확인이 필요한 대화상자(이유 포함). 실패한 항목은 선택된 채 남겨 재시도 가능. |
| 지원 안 함 | 비활성 + 이유 문장(예: "이 연결은 이동을 지원하지 않습니다"). 거짓 성공 금지. |
| 시스템 선택기 왕복 | 파일/폴더 선택기를 다녀와도 같은 폴더·선택·대기 작업이 유지돼야 한다. |

## 2. 레이아웃 선택표 (언제 무엇을, 왜)
| 창 | 레이아웃 | 이유 |
|---|---|---|
| 폰(접힘, <600dp) | 여러 줄 장면 보드. 장면을 누르면 미리보기와 스크롤 상세 편집, 뒤로 가면 같은 보드 위치. 재료 추가·내보내기는 하단 고정. | 적은 폭을 보드와 상세에 각각 충분히 쓴다. |
| 태블릿 세로(≈790dp) | 레일 + 본문. 위에 미리보기·스크롤 인스펙터, 아래 남은 공간에 여러 줄 보드. 위 영역을 접으면 보드가 확장된다. | 장면 목록을 유지하면서 선택한 장면을 고친다. |
| 태블릿 가로(≈1080dp) | 파일 탐색은 기존 소스 사이드바·본문. 편집기는 왼쪽 약 2/3 장면 보드, 오른쪽 약 1/3 미리보기·스크롤 인스펙터. | 많은 장면을 한눈에 찾고, 먼 위치는 번호로 바로 옮긴다. |
| 접힌 폰으로 돌아가기 | 위 규칙이 창 크기만으로 결정(기기 이름 분기 금지). | 폴더블·분할 화면에서도 같은 계약. |

- 편집 화면은 상태 표시줄(시계·배터리·시스템 아이콘)을 표시하고 안전 영역 안에 도구를 배치한다. 명시적 전체화면 재생에서만 상태 표시줄을 숨기며 돌아오면 복원한다. 2.32.0에서 TriFold 가로·세로와 Fold6 커버의 상태 표시줄·안전 영역을 확인했다. 키보드가 올라오면 미리보기를 줄이고 인스펙터를 스크롤하며, 헤더는 화면 위로 밀리지 않는다.

## 3. 파일 탐색 · 클립보드 · 선택
- 경로 막대(루트 연결 이름 › 폴더…)는 항상 보이고, 각 조각을 누르면 그 폴더로 이동. 상위 폴더 버튼 별도.
- 선택 모드: 닫기(×), "N개 선택", "전체 선택", 하단 행동 막대(복사·이동·삭제 …). 선택 표시는 체크 + 행 강조.
- 복사/이동은 클립보드 배너로 이어진다: **무엇을**(`‘파일명’ 외 N개`) · **어디로**(현재 폴더 경로) · `취소` · `여기에 복사/이동`. 폴더를 탐색하는 동안 배너가 유지된다.
- 소스가 다르면(폰하드→NAS) 목적지 선택지를 먼저 묻는다: NAS·네트워크 / 내 휴대폰 폴더 / 폰하드 안 다른 폴더. 각 선택지에 "ZIP 없이 원래 이름", "덮어쓰지 않고 번호" 같은 결과 문장을 붙인다.
- 폰하드↔NAS·내 폰 폴더는 위 목적지 선택으로 바로 복사·이동(업로드/다운로드)한다. 서로 다른 네트워크 연결 사이(NAS A → NAS B 등)는 자동 중계가 없으므로 "다운로드 → 업로드" 두 단계로 안내한다.
- 헤더 개수는 보이는 항목 수와 같아야 한다(폴더+파일을 두 번 세지 않는다).

## 4. 감상 계약 (재생·전체화면·복귀)
- 목록 탭 → 앱 내장 플레이어. 컨트롤: 닫기, 제목, 공유 / 이전·다음, 탐색 막대, 현재/전체 시간, 재생·일시정지, 재생 모드. 컨트롤은 화면 가장자리에 걸리지 않는다.
- 가로 전체화면에서도 같은 컨트롤. 세로 영상은 필러박스(자르지 않음).
- Back = 플레이어 닫고 **같은 목록 위치**로 복귀. 재열기 시 앱이 재생 위치를 복원할 수 있으면 복원(Android는 표시만 확인).
- 직접 연 로컬 영상이 내장 재생에 실패하면 시스템 플레이어 선택창으로 넘기며, 돌아오면 "다시 시도/닫기"를 남긴다. 원격 영상은 사용자가 버튼을 눌러야 외부 재생을 준비한다. 앱이 만든 영상은 **내장 플레이어에서 재생 가능한 인코딩**이어야 한다(H.264 ≤1080p는 Level 4.1 이하 요청. Fold6 인코더가 Level 6.0을 기록해 같은 기기 내장 재생이 실패한 사례).
- 재생 종료 후 다음 항목으로 이동하는 방식은 재생 모드로 선택한다. 자동으로 넘어간 다음 항목이 재생되지 않으면 앱 안에 오류와 외부 플레이어 버튼을 보여 주며, 시스템 선택창을 임의로 띄우지 않는다.

## 5. 영상 제작 계약 (가져오기 → 편집 → 렌더 → 저장 → 재열기)
- 진입: 새 프로젝트 + **최근 편집본 이어서 편집**(기존 편집본 목록 재사용, 별도 저장소 없음).
- 편집 상태 4종을 항상 구분 표기: 장면 미리보기 / 완성본(현재) / 이전 완성본(수정됨) / 내보내는 중.
- 완성본이 **현재(revision 일치)** 일 때만 공유·폰하드 저장·컬렉션 보관 활성. 수정되면 "다시 내보내기"를 먼저 안내. 이름만 바꾸면 완성본은 현재로 유지.
- 폰 편집기: 장면 보드와 상세 편집을 오간다(§13). 상세 편집은 미리보기 → 탭 → 스크롤 편집 패널이며, `재료 추가 / 내보내기`는 하단 고정. 완성본 행동 칩은 폭이 좁으면 **줄바꿈**한다.
- 저장 영수증: "폰하드에 저장됨"은 편집본 폴더의 영수증(완성본 리비전 + 폰하드 레코드 ID + 그 완성본 출력 파일 이름)으로 판단해 재열기 후에도 유지. 세 값이 모두 맞아야 저장됨이다 — 수정 없이 **다시 내보내기**한 새 완성본은 리비전이 같아도 출력 파일이 달라 다시 저장할 수 있다. 이름·크기만으로 중복을 추정하지 않는다. 폰하드 파일을 지우면 영수증은 무효가 되어 다시 저장 가능. 예전 2줄 영수증은 "저장 안 됨"으로 안전하게 취급.
- 렌더 결과 검증: 지정한 장면 순서·길이와 일치(프레임 대조), 출력 방향은 첫 소스 비율 규칙을 화면 형식 설정에서 바꿀 수 있음.

## 6. 오류·빈 상태
- 빈 폴더: "빈 폴더 / 이 폴더에는 표시할 파일이 없습니다." 보관함이 비어 보일 때는 목록을 다시 읽은 뒤에만 빈 상태를 보인다.
- 연결 불가·권한 없음: 원인과 다음 행동(다시 연결, 권한 허용)을 한 문장으로.
- 파괴적 실패(이동 중 원본 삭제 실패 등): 복사본이 남았다는 사실을 문장으로 알린다.

## 7. Android 실기기에서 확인한 것 vs 확인하지 않은 것
영상 처리 확인(2.31.1 APK, 2.31.2에서 해당 처리 코드 불변): 사진 카메라 무빙(§12) — 실제 사진 16:9→9:16 저장본·세로 사진→16:9 저장본 프레임 검사, 저장→수정 없이 다시 내보내기→닫기/재열기→다시 저장→재열기 저장됨, 예고편·뮤비 저장 파일명, 태블릿 세로 쌓기·가로 인스펙터·폰 커버 레이아웃, 기존 NAS 연결 유지.
이전 빌드에서 확인하고 코드가 바뀌지 않은 것(2.31.0): 폰 폭 편집기 스크롤·하단 고정 행동, 칩 줄바꿈, 최근 편집본 바로가기, 저장 영수증(저장→이름 변경→뒤로→재열기 유지), 폰 내장 재생(재생/탐색/뒤로), 패드 세로 쌓기 편집기·가로 편집기, 패드 NAS 폴더 만들기·복사·이동·이름 변경·삭제(취소 후 삭제)·기기에서 올리기·다운로드(번호 붙임)·폰하드→NAS 보내기, NAS 스트리밍 재생(세로/가로).
미확인: 펼친 Fold6, 접힌 TriFold, NAS↔NAS 다른 연결 간 복사, 재생 위치 복원, 접근성 글자 크기, 저장본의 순간 카메라 속도 실측(속도 한계는 단위 시험에서 렌더 경로를 표본 추출해 확인, 기기에서는 프레임으로 경로만 확인).

## 8. 이후 iPhone / iPad / Mac 적용 제안 (미구현 · 제안)
Android 사실을 **의미 계약**으로 가져가고 표현은 각 플랫폼 관용을 따른다.
| 계약 | iPhone | iPad | Mac |
|---|---|---|---|
| 한 열 스크롤 + 하단 고정 행동 | 탭 바/툴바 하단 | 세로: 쌓기 편집기 | — |
| 소스 사이드바 + 본문 + 인스펙터 | — | 가로: NavigationSplitView 3열 | 윈도우 3열, 크기 조절 |
| 선택·클립보드 배너 | 선택 모드 + 하단 툴바 | 동일 + 다중 선택 제스처 | Finder식 다중 선택, 키보드(⌘C/⌘V/⌫)·드래그 |
| 시스템 선택기 왕복 | 파일 앱/문서 선택기 | 동일 | 열기/저장 패널 |
| 삭제 확인 | 확인 시트 | 확인 시트 | 경고 시트(휴지통 정책은 별도 결정) |
| 토스트 | 배너/햅틱(방해 최소) | 동일 | 알림 센터는 쓰지 않고 창 내 표시 |
| 재생 | AVPlayer 전체 화면 | PiP·분할 | 창 재생 + 키보드 |
고려할 차이: 플랫폼 파일 권한 모델, 보안 스코프 URL, Mac 샌드박스. 위 표는 제안이며 구현 여부를 뜻하지 않는다.

## 9. 수용 체크리스트 (iPhone/iPad/Mac 구현 시)
- [ ] 복사는 원본 유지·이름 충돌 시 덮어쓰기 없음.
- [ ] 이동은 목적지 확인 후에만 원본 삭제, 실패 시 원본 보존 문장.
- [ ] 삭제 확인에 대상 이름/개수와 되돌릴 수 없음 표기, 취소 시 상태 불변.
- [ ] 클립보드 배너에 대상명·목적지 경로·취소·확정이 보임, 폴더 탐색 중 유지.
- [ ] 시스템 선택기 왕복 후 같은 폴더·선택·대기 작업 유지.
- [ ] 성공은 비차단 안내, 실패·부분 성공은 확인 대화상자.
- [ ] 헤더 개수 = 목록 개수.
- [ ] 폰 폭: 한 열 스크롤 + 하단 고정 행동 / 큰 세로: 쌓기 / 큰 가로: 사이드바+본문+인스펙터. 기기 이름이 아닌 창 크기로 결정.
- [ ] 앱이 만든 영상이 같은 기기 내장 플레이어에서 재생된다(인코더 프로필/레벨 점검).
- [ ] 완성본 현재/이전 구분, 이전 완성본의 공유·저장 비활성, 이름 변경은 완성본을 무효화하지 않음.
- [ ] "저장됨"이 재열기 후에도 유지(이름·크기 추정 금지).
- [ ] Back 시 같은 목록 위치로 복귀.


## 10. 같은 네트워크 권한 (Android 17)
- Android 17(targetSdk 37)은 같은 네트워크 통신에 `ACCESS_LOCAL_NETWORK` 권한이 필요하다. 없으면 TCP 연결은 되지만 응답이 막힌다(폰하드 "서버 열기"·NAS 연결 공통). 서버 열기와 연결 확인/저장 직전에 한 번 요청하고, 허용된 경우에만 대기 작업을 실행한다(거부하면 실행하지 않는다).
- 폰하드끼리 직접 잇는 "다른 기기 폰하드" 연결은 제공하지 않는다(후보에서 제거). 폰하드는 기존 서버 열기(웹 브라우저 접속)와 Finder 복사·이동·다운로드만 쓴다.

## 11. 저장 파일명·기본 제목
- 새로 만드는 저장 파일명과 자동 기본 제목: `yyMMdd-HHmmss-예고편`, 뮤직비디오 모드는 `yyMMdd-HHmmss-뮤비` (2자리 연도, 24시간, 기기 현지 시각). 예: `261031-104300-예고편.mp4`, `261031-104300-뮤비.mp4`.
- 적용: 폰하드 저장 파일명, 외부 공유 임시 파일명(캐시 키 폴더 아래 친근한 이름, 공유 제공자 허용 범위 `cache/shares` 유지), 완성본 컬렉션 보관 대화상자의 기본 제목(사용자 지정 제목이 있으면 그대로).
- 기존 파일·사용자 제목은 이름을 바꾸지 않는다(이관 없음). 같은 이름은 기존 "(1)" 보존 규칙.
- 실기기에서 예고편 3건과 뮤비 1건의 폰하드 저장 이름을 확인했다. 예고편 2건은 SAF로 내려받아 저장 이름과 영상 프레임까지 대조했다. 뮤비 이름은 폰하드 목록과 편집본 재열기에서 확인했다.

## 12. 사진 장면 카메라 무빙 (채우기/맞추기)
- **채우기는 어느 프레임에서도 레터박스가 없다.** 매 프레임 보이는 창은 사진 안에 있고(폭 ≤ min(1, 1/k), 높이 = 폭·k ≤ 1, k = 사진비/출력비), 축소는 꽉 차는 기준에서 멈춘다. 분석 실패·인물 여러 명·지정 구도·첫/끝 프레임·짧은 장면 모두 같다. 채우기가 자동으로 맞추기나 흐린 배경으로 바뀌지 않는다.
- **맞추기**는 사용자가 고른 경우에만, 사진 전체(레터박스 포함)를 보이며 살짝 확대·이동한다.
- 경로: 시작은 사진마다 고정된 무작위 구도(같은 사진은 미리보기·내보내기·재열기에서 같은 경로) → 다른 인물/주요 지점 → **마지막은 주인공**(가장 큰 얼굴 묶음, 머리 여백 포함). 인물이 없으면 가장 큰 검출 피사체, 그것도 없으면 사진 가운데(의미 보장 없음). 이동 중에는 꽉 차는 기준 쪽으로 살짝 빠졌다가(당기기) 다음 인물로 밀어 들어간다. 16:9→9:16은 가로로, 세로 사진→16:9는 세로로 움직인다. 분석은 기기 안(ML Kit)에서만 한다.
- **시간 고려(무리한 무빙 금지):** 어떤 순간에도 이동은 초당 화면 폭(세로 이동은 화면 높이)의 0.4배 이하, 확대·축소는 초당 |Δln(폭)| 0.12 이하. 장면 길이 안에 이 속도로 갈 수 있는 만큼만 들른다 — 중요한 인물부터 넣고, 못 들르는 인물은 건너뛴다(서두르지 않음). 시작 구도도 남은 시간으로 갈 수 있는 거리 안에서만 무작위다. 짧은 장면은 주인공 가까이에서 작게 움직이고, 0.5초 미만은 주인공 구도로 고정. 남는 시간은 이동을 더 느리게(최대 1.6배) 하고 마지막 머무름을 늘린다.
- 장면 길이: 새 자동 사진 장면은 최소 3초. 사용자가 정한 장면 길이는 자동으로 늘리지 않는다 — 짧게 정하면 들르는 인물이 줄어들고 편집기 표시(예: "인물 1/3곳 · 마지막 주인공")가 실제로 들르는 수를 그대로 말한다. 16:9 사진을 9:16으로 세 사람을 모두 들르려면 대략 20초 안팎이 필요했다.
- 지정 구도(보이는 위치)를 바꾸면 그 구도가 마지막 구도가 되고, 그 안의 인물이 잘리지 않을 만큼만 밀어 들어간다. 채우기 규칙은 그대로.
- 미리보기와 내보내기는 같은 계획·같은 행렬을 쓴다. 내보내기는 방향을 적용한 원본 사진 전체를 넣어 GL에서 한 번만 자른다(이중 자르기 없음).
- Apple 적용 시(미구현 · 제안): 같은 순수 기하(창 = 중심·폭, 매 프레임 사진 안으로 고정)와 같은 속도 한계·같은 사진별 시드를 쓰고, 얼굴/피사체 검출은 Vision으로 대체. 수용 기준은 아래와 같다.
  - [ ] 채우기 모든 프레임 네 모서리가 사진 픽셀.
  - [ ] 마지막 프레임에 주인공 얼굴 전체.
  - [ ] 렌더 경로를 표본 추출한 최대 이동·확대 속도가 한계 이하.
  - [ ] 같은 사진은 다시 열어도 같은 시작 구도, 사진마다 시작은 다름.

## 13. 장면 보드 편집 (2.32.0)
- **레이아웃:** 펼친 가로(폭 ≥ 840dp·높이 ≥ 480dp)는 왼쪽 약 2/3에 여러 줄 장면 보드, 오른쪽 약 1/3에 작은 장면/완성본 미리보기와 스크롤되는 기존 인스펙터. 펼친 세로는 위에 미리보기+인스펙터(접기 가능), 아래에 남은 높이를 쓰는 보드. 폰(세로 접힘)과 폰 가로·높이 560dp 미만 창은 보드가 화면을 채우고, 장면을 누르거나 "상세 편집"으로 미리보기+인스펙터 상세 화면을 열며, 뒤로 가기는 먼저 상세를 닫고 보드 스크롤을 유지한다. 폭이 좁은 창을 억지로 두 칸으로 나누지 않는다.
- **보드:** 지연 로딩 여러 줄 격자(수백 장면), 장면 번호(프로젝트 안 1부터의 순서이며 재료 개수가 아님)·재생 시간·원본 파일 이름·사진/영상 표시, 작게/보통 크기 전환, 번호 또는 파일 이름 검색, 입력한 번호로 바로 이동(그 장면의 고정 키를 선택), 회전·상세 복귀 시 스크롤 유지.
- **다중 선택 이동:** 선택한 장면들을 원래 순서 그대로 하나로 묶어 옮긴다. 입력하는 번호는 "첫 번째 선택 장면이 놓일 최종 위치"(1 ~ 전체−선택+1)이며 범위를 벗어나면 이동 버튼이 꺼진다. 한 번의 이동이 한 번의 실행 취소 단위이고, 선택은 장면 키를 따라간다. 복제·장면 삭제(원본 파일은 지우지 않음)도 한 번의 편집이다. 끌어서 옮기기는 이번 범위에 없다(정확한 번호 이동 우선).

## 14. 장면 자막 (2.32.0)
- 장면마다 선택 사항인 수동 자막 하나. 그 장면 전체 길이 동안 출력 화면 기준으로 고정되며 사진 무빙·화면 위치와 함께 움직이지 않는다. 자동 음성 인식은 없다.
- 인스펙터 "자막" 탭: 여러 줄 입력(최대 2000자), 오늘 날짜/실제 촬영일(또는 촬영 기간) 삽입(커서 위치에 삽입, 촬영 시각을 모르면 버튼이 꺼지고 날짜를 지어내지 않음), 프리셋(가독성·시네마·여행 — 모양만 바꾸고 글은 유지), 글꼴(프리텐다드 보통/굵게, 시스템 명조·고정폭), 크기 4단계(출력 짧은 변 기준, 기기 밀도와 무관), 글자 색(견본 + #RRGGBB), 그림자 켜기/색/진하기, 줄 간격, 5×5 위치.
- 고친 내용은 미리보기에만 먼저 보이고 "적용"을 눌러야 저장된다(글자마다 실행 취소를 쌓지 않음). 범위는 현재 장면(기본)/선택한 장면 n개/전체 중 고르고, 글과 모양 전체가 한 번의 실행 취소 단위로 들어간다. 빈 내용으로 적용하면 자막이 지워진다. 적용하지 않은 채 다른 장면을 고르면 그 장면에는 옮겨지지 않고, 원래 장면으로 돌아가거나 버리도록 안내한다. 적용·취소 버튼은 입력창 위에 있어 키보드에 가려지지 않는다.
- 렌더링: 미리보기와 내보내기가 같은 비트맵 렌더러(출력 크기 그대로의 투명 비트맵, 가장자리 8% 안전 영역 안에서 줄바꿈, 넘치면 글자를 줄여 화면 밖으로 잘리지 않게)를 쓴다. 내보내기는 사진 무빙/화면 위치 효과 **다음에** 겹친다. 완성본 재생에는 다시 겹치지 않는다. 편집본 저장(JSON)에 선택 항목으로 기록되고, 예전 편집본은 자막 없음으로 열린다.
- **실기기 확인(2026-10-31):** Fold6 커버와 TriFold 가로·세로에 2.32.0 설치·재실행, 설치 APK 해시 일치. 기존 455장면 편집본은 읽기 전용으로 보드 16장면 동시 표시와 420번 검색을 확인했다. 원본 편집본의 순서는 바꾸지 않았다.
- 별도 합성 재료 3개로 3번→1번 이동·실행 취소, 자막 전체 적용, 닫고 재열기 유지, 첫 장면만 수정·다시 제작·폰하드 저장을 확인했다. 저장 파일 `261031-170331-예고편.mp4`를 정상 다운로드하여 H.264/AAC·1920×1080·10.83초를 확인했고, 0.5/4.5/8.5초 프레임에서 첫 장면 Caption B, 나머지 Caption A를 대조했다. Fold6에서도 날짜 삽입·여행 스타일·제작을 확인했다.
- 최종 배치 보완 후 TriFold 가로에서 자막 입력 키보드가 떠도 상태 표시줄·헤더·장면 보드가 유지되는 것, 세로 쌓기 배치와 Fold6 보드의 중복 도구 제거를 화면으로 확인했다. 회전 점검 후 원래 자동 회전 상태로 복구했다.
- **범위 한계:** 실제 420→3 이동은 사용자 편집본 보호를 위해 수행하지 않았으며, 다중 선택 이동은 순서 보존·실행 취소 코드 경로를 확인했다. 자동 음성 자막, 드래그 재정렬, Apple 적용은 이번 범위가 아니다. 전체 자동 시험 실행을 뜻하지 않는다.
